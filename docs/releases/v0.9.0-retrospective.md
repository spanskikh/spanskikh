Post-release engineering retrospective for Release `v0.9.0` (*Agentic SDLC Adoption with Antigravity CLI `agy` & Unified `FastMCP` `stdio` Multi-Agent Product Orchestration*, `CR-027`, `CR-024`, `CR-025`, `CR-026`), implementing process controls **`CAPA-008`** and **`CAPA-009`**.

## Antigravity CLI (`agy` v1.5.13) Adoption in the Agentic SDLC

### 1. Root Motivation: Eliminating Copy-Paste Vibecoding Friction
Prior to `v0.9.0`, multi-repository development across the 5-repository cluster relied on manual copy-paste round-trips between chat windows and KDE Konsole terminals. Even with the `<= 1.5 KiB` PTY paste cap (`CAPA-003`), manual shell pasting introduced high cognitive overhead, repetitive context re-seeding across repositories, and ad-hoc verification commands. The primary Track A goal of `v0.9.0` was to replace manual copy-paste loops with an auditable, workspace-aware SDLC agent operating under strict human governance.

### 2. Tool Selection Rationale (`agy` v1.5.13 vs. Alternatives)
- **Antigravity CLI (`agy` v1.5.13, FastMCP-Native):** Selected as the primary coding and verification agent because it natively speaks Model Context Protocol (`agy mcp add|list|enable|disable|remove`), auto-loads workspace instruction anchors (`GEMINI.md` and `AGENTS.md` with symlink deduplication), supports explicit execution modes (`--mode plan` vs. `--mode accept-edits`), and enforces deterministic command allow/deny boundaries in `~/.config/antigravity/settings.json`.
- **Deferred & Scoped Alternatives:** `Aider` was formally deferred to avoid overlapping git-mutation workflows. Local `Ollama` (`qwen2.5-coder:7b` and `nomic-embed-text` on `hippo`) remains strictly scoped to product domain synthesis and grammar-constrained LLM-as-a-Judge evaluation (`CAPA-006`), keeping zero paid cloud API dependencies in product runtime and test suites.

### 3. Actual Usage & Two-Phase Prompting Workflow (`CAPA-008` & `CAPA-009`)
Across `CR-027`, `CR-024`, `CR-025`, and `CR-026`, `agy` was executed from the workspace root (`~/projects` with `--add-dir ~/projects`) using a disciplined two-phase gate:
1. **Phase 1 — Read-Only Plan & Contract Audit (`--mode plan`):** `agy` read `spanskikh/DEVPROCESS.md`, `spanskikh/docs/releases/v0.9.0-refine.md`, and target repository contracts (`contracts.py`, `server.py`, existing test suites per `CAPA-002`) and emitted a file-by-file implementation and verification plan without modifying disk state.
2. **Phase 2 — Accept-Edits Implementation & Logged Verification (`--mode accept-edits`):** `agy` authored the target Python modules, CLI wrappers, unit/contract tests (keeping Python string literals `<= 85` chars), and `docs/dev-log/` artifacts, executed `.venv/bin/ruff`, `.venv/bin/mypy --strict`, and `.venv/bin/pytest` via `./scripts/run_logged.sh`, updated `CHANGELOG.md`, and halted at the Human-in-the-Loop (HITL) Git boundary.

### 4. Remaining Manual Human-in-the-Loop (HITL) Perimeter
While `agy` automated contract reading, multi-file editing, and logged test execution, the human architect retained exclusive control over:
- Reviewing `git status` and `git diff` across every modified repository after Phase 2 completion.
- Executing all mutating Git lifecycle commands (`git commit`, `git tag`, `git push`), which are blocked for agents both normatively in `DEVPROCESS.md` and technically in `~/.config/antigravity/settings.json`.
- Authoring final release sign-off judgment and approving cross-repo promotion.

### 5. Verification of `CAPA-008` and `CAPA-009` Implementation
- **`CAPA-008` (Workspace Root Launch & Two-Phase Plan-Then-Edit Gate):** Implemented by tracking canonical `spanskikh/GEMINI.md` (`7dfa24e`), symlinking `~/projects/GEMINI.md` and `~/projects/AGENTS.md`, codifying `--add-dir ~/projects` and `--mode plan` -> `--mode accept-edits` in `DEVPROCESS.md` (`6b5f2a6`), and logging `CAPA-008` in `docs/DEFECTS_AND_CAPA.md`.
- **`CAPA-009` (Agent Prompt Auditability & Phase-Log Traceability):** Implemented by codifying canonical phase prompt templates and `logs/vX.Y.Z-crNNN-{plan,edit}.log` archival rules in `docs/DEFECTS_AND_CAPA.md`, `DEVPROCESS.md`, and `GEMINI.md`, and compiling the complete `v0.9.0` Phase Prompt & Log Traceability Table below.

## Lessons Learned
- **Workspace Root Launch Prevents Rule Truncation (`CAPA-008`):** Antigravity CLI (`agy`) walks upward for `GEMINI.md` and `AGENTS.md` until it hits a `.git` directory. Launching from `~/projects` (`--add-dir ~/projects`) with symlinks pointing to `spanskikh/GEMINI.md` guarantees all 5 repositories inherit the same SSoT process rules without violating `CAPA-004` anti-duplication.
- **Two-Phase Plan-Then-Edit Eliminates Contract Guesswork (`CAPA-002` / `CAPA-008`):** Running a read-only `--mode plan` pass to inspect `contracts.py` and `server.py` across all 4 repos before writing the `CR-025` `FastMCP` `stdio` Supervisor enabled first-pass `mypy --strict` and `pytest` success across 650 lines of async MCP orchestration code.
- **Phase Prompt & Dual-Log Archival Completes Forensic Traceability (`CAPA-009`):** Pairing `./scripts/run_logged.sh` tool logs with archived Phase 1 (`-plan.log`) and Phase 2 (`-edit.log`) agent transcripts and prompt summaries makes agent-assisted releases reproducible during technical due diligence.
- **Sibling-Aware CLI Delegation with Isolated CI Fallback (`CR-026`):** Delegating `test_sbom_and_contracts.py` in `abstract-ops`, `interview-ops`, and `hostel-ops` to `sandbox-init/src/sandbox_init/sbom.py` when present in a multi-repo checkout—while retaining a lightweight local fallback for single-repo GitHub Actions runners—eliminates duplicated logic without coupling CI checkouts.

## Rejected Ideas
- **Duplicating `GEMINI.md` Inside Every Dev Repository:** Rejected because independent copies would drift and violate the `CAPA-004` / `CAPA-005` Single Source of Truth architecture; workspace-root symlinks (`~/projects/GEMINI.md` -> `spanskikh/GEMINI.md`) solved discovery cleanly.
- **Granting `agy` Autonomous `git commit` / `git push` Permissions:** Rejected to preserve a hard Human-in-the-Loop (HITL) security and quality gate over Git history and release tags.
- **Requiring Live `rhino` PostgreSQL for Offline `CR-025` Supervisor Contract Tests:** Rejected in favor of an offline-safe `stdio` harness for `hostel-ops` during unit/contract tests so the 4-hop `FastMCP` `stdio` Supervisor runs deterministically in offline CI.

## Unlucky Probe-Runs
- **Child-Directory `agy` Launch:** An early probe launched inside a child repository directory missed workspace-level `~/projects/GEMINI.md` rules due to `.git` boundary termination, directly motivating `CAPA-008`.
- **Unfiltered `pytest` Run Triggering Cold-Load Ollama Timeout (`20261123-140011_cr026_pytest_fast.log`):** Running `pytest` without `-m "not integration"` during a fast check invoked `test_live_ollama_doc_rubric_and_counterexample` against an un-warmed `Ollama` daemon and hit `httpx.ReadTimeout`, motivating an automated pre-integration `Ollama` warmup ping in `v0.10.0`.
- **Split Phase Log Destinations:** `CR-024` phase logs were written to `sandbox-init/logs/v0.9.0-cr024-{plan,edit}.log` whereas `CR-025` and `CR-026` plan logs were written to `spanskikh/logs/v0.9.0-cr02{5,6}-plan.log`, motivating `CAPA-009` standardization.

## Residual Risks & Forward Backlog (`v0.10.0`)
- **Automated Enforcement of `CAPA-009` & Pre-Release Hygiene (Track A):** `v0.10.0` will add an automated pre-release audit gate verifying phase-log archival, `<= 85` char Python string literals, `RELEASES.md` / `CHANGELOG.md` synchronization, and an `Ollama` warmup ping before live `CAPA-006` tests.
- **Cross-Agent Traceability, Red-Teaming & Business UAT (Track B):** `v0.10.0` will add `OpenTelemetry`/`OpenInference` `trace_id` propagation across `FastMCP` `stdio` hops, `PyRIT` adversarial red-teaming gates, Golden Trace replay, and an automated End-to-End Business UAT suite validating the practical workflows in [`docs/PRODUCT_GUIDE.md`](../PRODUCT_GUIDE.md) prior to `v1.0.0` freeze.
