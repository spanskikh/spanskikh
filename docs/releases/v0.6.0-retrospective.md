# Release Retrospective — `v0.6.0` (`CR-014` .. `CR-016`: Public Release Readiness, Showcase Synchronization & Supply-Chain Hardening)

Post-release engineering analysis covering lessons learned, rejected ideas, unlucky probe-runs, and key decisions from the `v0.6.0` public release cycle.

## 1. Lessons Learned
- **Pre-Public Hygiene & PII Gate (`CR-014`):** Running an automated regex/AST hygiene audit (`tests/test_release_hygiene.py`) across all tracked files before flipping repository visibility prevented local workstation paths (`/home/<user>/`), real DSN credentials, and draft artifacts from leaking into public git history.
- **Explicit GitHub Actions Enablement on Visibility Flip (`CR-016`):** Transitioning a repository from `private` to `public` does not automatically enable GitHub Actions if permissions were previously restricted; explicitly verifying and enabling `/repos/{owner}/{repo}/actions/permissions` guarantees immediate CI execution on tag push.
- **Non-Interactive CLI Determinism (`DEVPROCESS.md`):** Enforcing `GH_PAGER=""`, `PAGER=cat`, and `git config --global core.pager cat` eliminated interactive pager hangs during batch cross-repository GraphQL and `gh` verification runs.
- **Read-Only GraphQL Showcase Verification:** Because GitHub's public GraphQL `Mutation` schema exposes `pinIssue`/`pinEnvironment` rather than user profile repository pinning, combining one-time UI pin selection with automated `viewer.pinnedItems` GraphQL assertions provides reproducible showcase observability.

## 2. Rejected Ideas
- **Keeping Legacy Experimental Repositories Public Alongside the Core Cluster:** Rejected leaving older prototypes (`InterviewOps`, `Garden`, `mcp-qa-automation-engine`, `SwagLabs`) public; privatized all legacy repositories so `github.com/spanskikh` presents a focused, verified 4-repository neuro-symbolic portfolio.
- **Assuming `uv.lock` Presence in CI Workflows:** Rejected hardcoding `uv.lock` cache/sync steps in `.github/workflows/ci.yml` because repositories use standard `pyproject.toml` editable installs (`pip install -e ".[dev]"`), which caused early CI setup failures before standardization.

## 3. Unlucky Probe-Runs
- **Probe 1 (`abstract-ops` GitHub Actions Disabled After Visibility Flip):** Initial `v0.6.0` push to `abstract-ops` did not trigger CI because Actions were disabled on the repository; resolved via `gh api -X PUT repos/spanskikh/abstract-ops/actions/permissions -f enabled=true` followed by an empty trigger commit (`Run 45045574506` -> `success`).
- **Probe 2 (`pinItem` Missing on GraphQL `Mutation` Type):** Attempting to pin profile repositories via `pinItem` returned `Field 'pinItem' doesn't exist on type 'Mutation'`; introspected `__type(name: "Mutation")` to confirm the schema boundary, pinned via UI, and verified via `viewer.pinnedItems`.
- **Probe 3 (`jq` Missing on Workstation During GraphQL Inspection):** Initial GraphQL JSON parsing failed until `app-misc/jq` was installed via `sudo emerge -av app-misc/jq`, enabling deterministic JSON filtering in shell pipelines.

## 4. Release Chat Digest

- Synchronized `README.md` and `docs/ARCHITECTURE.md` across all 4 repositories (`CR-015`) and passed offline + live `Ollama` doc rubric gates.
- Promoted `sandbox-init`, `abstract-ops`, `interview-ops`, and `hostel-ops` to `PUBLIC` (`CR-016`), privatized 4 legacy repositories, verified green CI runs across all 4 repos, pinned the showcase on `github.com/spanskikh`, and updated `CV5-SergeiPanskikh-AIQA_2.pdf`.
