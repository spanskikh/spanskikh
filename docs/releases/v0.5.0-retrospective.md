# Release Retrospective — `v0.5.0` (`CR-010` .. `CR-013`: Protocol Contracts, RRF IR Gate, Adversarial Fuzzing & SDLC Governance)

Post-release engineering analysis covering lessons learned, rejected ideas, unlucky probe-runs, and key decisions from the `v0.5.0` release session.

## 1. Lessons Learned
- **End-to-End `stdio` MCP Verification (`CR-010`):** Testing `FastMCP` servers over real `mcp.client.stdio` JSON-RPC pipes (`list_tools()` + `call_tool()`) exposes wire-level schema and serialization mismatches that direct Python function calls cannot detect.
- **Quantitative IR Gating (`CR-011`):** Evaluating hybrid `pgvector` + `tsvector` (`RRF k=60`) against a curated 16-query Golden Dataset over live `hippo <-> rhino` infrastructure proved `Recall@3 = 0.9375`, `MRR = 1.0000`, and `p95 = 72.217 ms`, establishing an objective anti-hallucination baseline before LLM synthesis.
- **Adversarial & Property-Based CEGIS Bounds (`CR-012`):** Combining 60 deterministic attack specs (MFA bypasses, priority collisions, boundary off-by-one overlaps, shadowed rules) with 120 `Hypothesis` fuzzed specs verified `0` false `SAT` verdicts and bounded CEGIS convergence in `2` iterations (`<= 3`).
- **Cross-Session Context Governance (`CR-013` / `CAPA-002`):** Codifying `DEVPROCESS.md` eliminated unverified contract assumptions (`Zero-Guesswork Contract Rule`) and prevented Russian language drift in Git commits and documentation.

## 2. Rejected Ideas
- **Updating Public `CHANGELOG.md` and `RELEASES.md` on Every Intermediate CR:** Rejected premature updates on intermediate CRs to avoid redundant commits and repeated 2-minute CPU `Ollama` doc rubric evaluations; consolidated showcase documentation updates into the single `v0.5.0` closure gate.
- **Sharing Root-Owned Docker DuckDB Files with Host Pytest Runs:** Rejected writing host `pytest` telemetry directly into `/app/data/*.duckdb` files owned by container `root`; isolated host integration telemetry paths via `AUDIT_DB_PATH`.

## 3. Unlucky Probe-Runs
- **Probe 1 (`POSTGRES_DSN` Credential Mismatch in Live RRF Test):** Initial live run defaulted to `dev:dev` instead of `.env` credentials (`dev:devpass`), failing fast with `psycopg.OperationalError`; resolved by sourcing project `.env` DSN parameters.
- **Probe 2 (`Permission denied` on Container-Owned `audit.duckdb`):** Writing host benchmark telemetry to `sandbox-init/data/audit.duckdb` failed due to container file ownership; resolved by directing host test telemetry to a user-writable DuckDB path (`EXIT_CODE: 0`).
- **Probe 3 (`E501` Line Length `102 > 100` in `benchmark.py`):** Function signature `compute_recall_at_k` exceeded 100 characters by 2 columns; wrapped signature cleanly before merging `CR-011`.

## 4. Release Chat Digest

- Built `src/interview_ops/benchmark.py`, `tests/test_rrf_benchmark.py`, and `rag_benchmarks` DuckDB telemetry (`CR-011`), passing live `hippo <-> rhino` `pgvector` + `Ollama` gates.
- Built `src/abstract_ops/adversarial.py` and `tests/test_adversarial_cegis.py` (`CR-012`) with `0` false `SAT` verdicts and `2`-iteration CEGIS convergence.
- Passed offline (`ruff`, `mypy --strict`, `pytest`) and live `Ollama` doc rubric gates across all 4 repos and pushed annotated tag `v0.5.0`.
